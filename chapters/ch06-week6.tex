\chapter{Week 6: Mutable State}
\label{ch:week6}

Lecture 6: October 13, 2026. Recitation 6: October 16, 2026.

Supplementary reading:
\begin{itemize}
  \item \cite{PLAI} Chapter 8 (Mutation: Structures and Variables), Section 8.1 in particular, which adds boxes to the closure interpreter with a store as this chapter does.
  \item \cite{SICP} Section 3.1 (Assignment and Local State), for what assignment costs: an expression can no longer be replaced by its value.
  \item \cite{Reynolds}, optional: the paper that names the problem of \Cref{sec:metacirc}, an interpreter that silently inherits features of the language it is written in.
\end{itemize}

Every interpreter so far has been \emph{pure}: evaluating an expression produced a value and nothing else, so the same expression in the same environment always gave the same answer. This chapter adds the smallest piece of mutable state, the box of \Cref{sec:scopestate}, to the closure interpreter of \Cref{sec:closures}. The first attempt stores a box's contents directly in the value and cannot express \code{set-box!}. The fix is a second table next to the environment, the \emph{store}, which maps locations to values and is passed into and out of every evaluation step. We then write the same interpreter a second time using Racket's own boxes, and compare the two. This chapter covers:
\begin{itemize}
  \item \Cref{sec:stateboxes}: the four new constructs, the examples, and a first attempt that cannot mutate;
  \item \Cref{sec:storepass}: store-passing style, with locations, \code{fetch}, the \tyname{Result} type, and threading the store through arithmetic, \code{let}, and application;
  \item \Cref{sec:storeboxes}: the box clauses of the store-passing interpreter, with traces showing where the environment and where the store come from;
  \item \Cref{sec:metacirc}: the meta-circular interpreter, which implements boxes with Racket boxes and functions with Racket functions, and what each version explains;
  \item \Cref{sec:rec6}: Recitation~6, mutable variables with \code{set!}, evaluation order, immutable tables versus boxes, and store-passing with \code{mret} and \code{mbind}.
\end{itemize}
